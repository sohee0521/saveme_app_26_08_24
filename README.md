# SAVE ME

> **"내일의 나를 구하는 가장 빠른 걸음"**  
> 오늘 안 하고 하루를 미뤘을 때 미래의 내가 감당해야 할 대가를 시각화해 주는 일정 관리 웹앱

- **듀얼 게이지(Dual-Gauge) 비교**:
  - **계획 게이지**: 현재 시점에서 권장 목표 진도율(%).
  - **현재 게이지**: 사용자가 실제로 완료한 작업 진행률(%).
- **[미루기 (+1일)] 인터랙션**:
  - 오늘 하루를 완전히 쉬었다고 가상 시뮬레이션하여 미래의 하루 권장 작업량과 위험도 변화를 확인.

- **돌아가기 모달**:
  - 잔여 일수가 `0일`에 도달하면 화면이 암전되며, 포기 대신 행동을 유도하는 _"미래의 나를 구하러 가볼까요?"_ 모달 팝업.

### 3. 4단계 위험도 시스템

계획 게이지와 현재 진행률의 격차($\text{Gap} = \text{계획 진도율} - \text{현재 진행률}$)에 따라 캐릭터 표정과 배경 테마가 실시간으로 변화.

|   단계    |   상태   | 캐릭터 & 테마 무드            | SOS 멘트 예시                                       |
| :-------: | :------: | :---------------------------- | :-------------------------------------------------- |
| **1단계** | **여유** | 계획대로 순항 중, 편안한 표정 | _"계획대로 사는 사람의 품격이란 이런 것"_           |
| **2단계** | **긴장** | 살짝 밀림, 집중 필요          | _"'내일의 내가 하겠지'의 '내일'이 바로 오늘입니다"_ |
| **3단계** | **위기** | 경고 깜빡임                   | _"야... 장난치지 마. 나 내일 잠 진짜 못 자."_       |
| **4단계** | **파멸** | 경고 & 화면 진동              | _"나.. 다시 돌아갈래..."_                           |

## 3. 핵심 계산식

### 1) 계획 진도율 계산식

등록일부터 마감일까지의 전체 기간 동안 **오늘 시점(또는 가상 미루기 시점)에 도달해야 할 이상적인 목표 진척도**를 계산합니다.

$$\text{전체 배정 일수} = (\text{마감일} - \text{등록일}) + 1$$

$$\text{하루 목표량(\%)} = \frac{100\%}{\text{전체 배정 일수}}$$

$$\text{경과 일수} = \text{실제 경과 일수} + \text{미룬 일수} + 1$$

$$\text{계획 진도율(\%)} = \min(100, \text{경과 일수} \times \text{하루 목표량(\%)})$$

> _단, 잔여 일수가 0일 이하이거나 경과 일수가 전체 기간을 초과하면 계획 진도율은 100%로 고정된다._

---

### 2) 지연 격차 및 4단계 상태 판정 로직

계획 진도율과 현재 진행률의 차이와 하루 필요 작업 시간을 결합하여 4단계 위험도를 판별.

$$\text{Gap} = \text{계획 진도율(\%)} - \text{현재 진행률(\%)}$$

$$\text{지연 일수}(\text{delayDays}) = \frac{\text{Gap}}{\text{하루 목표량(\%)}}$$

|   상태   | 판정 기준 (OR 조건)                                                                                     | 의미 및 메시지                                                                     |
| :------: | :------------------------------------------------------------------------------------------------------ | :--------------------------------------------------------------------------------- |
| **여유** | $\text{Gap} \le 0$ 또는 현재 진행률 $100\%$<br>또는 하루 필요 시간 $\le 40\text{분}$                    | **"지금처럼만 하면 여유롭게 끝내요"**<br>계획보다 앞서거나 남은 작업량이 적음      |
| **긴장** | $\text{지연 일수} \le 1.0\text{일}$<br>또는 하루 필요 시간 $\le 180\text{분}(3\text{시간})$             | **"살짝 밀렸지만 오늘 부지런히하면 원상복구 가능해요"**<br>하루치 내외의 지연 발생 |
| **위기** | $\text{지연 일수} \le 2.5\text{일}$<br>또는 하루 필요 시간 $\le 360\text{분}(6\text{시간})$             | **"휴식은 반납하고 풀가동하면 수습은 가능해요"**<br>상당한 집중 작업 필요          |
| **파멸** | $\text{마감일 초과}(\text{남은 일수} < 0)$<br>또는 위기 기준 초과 ($> 2.5\text{일}$ & $> 6\text{시간}$) | **"24시간 잠과 영혼을 갈아넣어도 모자라요"**<br>물리적 한계 도달 (화면 진동/경고)  |

## 5. 느낀 점

#### 기간 스케일에 따른 상태 설정

- **문제 인식**: 일정 기간이 3일짜리 단기 과제부터 3개월 이상의 장기 프로젝트까지 스케일 차이가 매우 컸다.
- **배운 점**: 단순히 지연된 일수만으로 상태를 판정하면 단기 일정은 하루만 밀려도 '파멸'이 되고, 장기 일정은 일주일을 밀려도 '여유'로 뜨는 왜곡이 발생했다. 이를 해결하기 위해 전체 기간 대비 하루 목표 진도율과 실제 남은 물리적 시간을 결합해 조건을 여러개 두는 것으로 변경하였다.이를 통해 **초기 기획 단계에서 다양한 케이스를 정의하는 것의 중요성**을 배웠다.

#### 기획자,개발자 시야를 벗어난 UX/UI 설계

- **문제 인식**: 기획부터 개발까지 직접 진행하다 보니 구조가 익숙했지, 서비스를 처음 접하는 사용자 입장에서는 _'미루기 예측이 무엇인지'_, _'두 게이지의 차이가 무엇인지'_ 직관적으로 이해하기 어려울 수 있다는 점을 인지했다.
- **배운 점**: Info 아이콘, 애니메이션 제공(경고 펄스, 암전 연출), 쉬운 SOS 캐릭터 멘트 등을 보강했다. 이를 통해 "별도의 설명서 없이 인터랙션만으로도 의도가 전달되는 친절한 UX"를 고민하게 되었다.

#### 입력값 검증과 폼 예외 처리

- **문제 인식**: 프로젝트 등록 과정에서 작업 일수, 하루 작업 시간, 마감일 등 다양한 인풋을 다루며 비정상적인 값(0 이하의 일수, 24시간 초과, 날짜 역전 등)을 방어해야 하는 예외 처리 요소가 많았다.
- **배운 점**: `NumberStepper` 컴포넌트 모듈화, 실시간 유효성 검사, 포커스 제어 및 범위 자동 보정(`Math.min/max`)을 적용하며 예외처리의 중요성을 알게되었다.

#### 날짜 갱신 라이프사이클과 D-Day 시간 단위 세밀함

- 마감 직전에는 분/초 단위의 긴박함이 중요한데 '1일 단위'로만 다뤄진 점이 아쉬웠다.
